# AIO提案先リスター（aio-target-lister）

## このスキルの目的

営業が詰まるのは商品知識でも気合いでもなく、**今日誰に出すかが決まっていない**こと。
頭の中の「あの会社どうかな」は月3〜5社が限界だが、送信箱には過去の取引先が
何十倍も眠っている。それを全部並べて、相性順に切る。

出すものは**台帳1本**。眺めて満足する資料ではなく、上から順に連絡すれば
提案数が積み上がる作業リストとして作る。

```
STEP 0  事前チェック（Python・Gmail接続・作業フォルダ）
STEP 1  前提を確定（期間・商材）
STEP 2  Gmailの送信済みを全ページ走査（本文はコンテキストに入れない）
STEP 3  extract_domains.py で社外ドメインに畳む
STEP 4  商材仕様から相性を判定
STEP 5  build_ledger.py で台帳HTMLを組む
STEP 6  ブラウザで検証して納品し、使い方と次の一手を伝える
```

## 利用者について（最初に読む）

このスキルは**ライトアップ社内の営業と、AIOマスターを販売するパートナー企業の
両方に配布している**。利用者の多くは営業職で、ターミナルやPythonに詳しくない。
だから次を守る。

- **利用者固有の値をスキルに書き込まない。** アドレス・自社ドメイン・フォルダは実行時に判定する
- **利用者にコマンドを打たせない。** コマンドはすべてこちらで実行し、結果だけを平易に伝える
- **ステップごとに1行で進捗を伝える。** 「送信済みメールを読み込んでいます（3/8ページ）」のように。
  数分かかる作業なので、黙っていると止まったと思われる
- **専門用語を言い換える。** 「ドメイン」→「メールアドレスの@より後ろ（会社ごとの住所）」、
  「バウンス」→「届かずに戻ってきたメール」。初出だけ言い換えれば十分
- **詰まったら利用者のせいにしない。** 下の「困ったとき」の表で解決し、
  解決しなければ何が起きているかを1文で伝えて、次に何をすればいいかを示す

使い方そのものを聞かれたら（「どう使うの？」「台帳の見方は？」）、
`references/partner_guide.md` の内容で答える。台帳を作らずに説明だけしてよい。

## STEP 0｜事前チェック

初回でも2回目以降でも毎回やる。数秒で終わる。

### 0-1. Python

`python --version` → 失敗したら `python3 --version` → Windowsなら `py --version` の順に試し、
**最初に動いたものを以降のコマンドで使う**（以下 `<python>` と書く）。
3.8以上なら可。追加のライブラリは要らない。

Windowsで `python` を打つと Microsoft Store が開くだけのことがある。
それは「入っていない」扱いにして次を試す。どれも動かなければ、利用者に：

> Pythonが入っていないため、台帳を作れません。python.org から最新版をインストールしてください
> （Windowsでは、インストール画面の最初にある「Add python.exe to PATH」に必ずチェックを入れてください）。
> 終わったら、Claude Codeを再起動してもう一度「AIOの提案先リストを作って」と送ってください。

### 0-2. Gmailの接続

ToolSearch で `gmail search_threads` を検索し、説明文にGmail（メール）とある
`search_threads` を使う。ツール名の前半（`mcp__xxxx__`）は利用者ごとに違うので、
**名前を決め打ちしない**。Google Driveの検索ツールと取り違えないこと。

見つからない、または「認証が必要」と出たら、利用者に：

> Gmailがまだつながっていないようです。claude.ai の「設定」→「コネクタ」で Gmail を
> 追加（または再接続）し、自分のGoogleアカウントでログインしてください。
> 終わったら、この画面で「つないだ」と送ってください。

### 0-3. 作業フォルダ

台帳と中間ファイルは次に置く。利用者があとで自分で開けるように、分かりやすい場所にする。

- `~/Documents` があれば `~/Documents/AIO提案先台帳/<YYYY-MM-DD>/`
- なければ `~/AIO提案先台帳/<YYYY-MM-DD>/`

同じ日に2回作ったら `<YYYY-MM-DD>_2` のように分ける。上書きしない。

## STEP 1｜前提を確定する

既定値で進めてよい。違うときだけ聞く。聞くときも1問だけにする。

| 項目 | 既定 |
|---|---|
| 期間 | `newer_than:1y` |
| 母集団 | 送信済みのみ（**送ったことのある相手**＝面識がある相手だけを対象にする） |
| 商材 | AIOマスター |
| 自分のアドレス | STEP 3で送信済みメールから自動判定（聞かない） |

受信メールを入れないのは意図的に。AIOは飛び込みで売るのに一番向かない商材で、
「御社、AIに出てきませんよ」は初対面だとただの因縁になる。すでに相談される
関係がある相手に絞るほうが、結果的に受注率が高い。

勉強会の実演で使う場合は、**その場で流れが見えること**が価値なので、
期間を `newer_than:120d` に縮めて時間を短くしてよい。

## STEP 2｜送信済みを全ページ走査する

`search_threads` を `query: "in:sent newer_than:1y"` / `pageSize: 50` で、
`nextPageToken` が返らなくなるまで回す。だいたい300〜400スレッド、8〜10ページ。
ページごとに「送信済みメールを読み込んでいます（N/約M ページ）」と伝える。

**viewの選び方**：1ページ目を取ったら、保存されたファイルを1件だけ覗いて
`toRecipients` と `subject` と `sender` が入っているか確認する。入っていないviewで全ページ
回すと、宛先が取れず最初からやり直しになる。`THREAD_VIEW_MINIMAL` で足りることが多い。

**結果はコンテキストに読み込まない。** 大きいツール結果はセッションの
`tool-results/` に `.txt`（中身はJSON）で保存される。400スレッドの本文を読むと
それだけで文脈が埋まり、肝心の判定が雑になる。集計は次のSTEPでスクリプトにやらせ、
こちらは出力サマリだけ見る。

**保存先の探し方**（利用者ごとにパスが違うので決め打ちしない）：

```bash
ls -dt ~/.claude/projects/*/*/tool-results 2>/dev/null | head -3
```

いちばん新しいフォルダに `*search_threads*` のファイルがページ数ぶんあれば、それが今回の分。
**古いセッションのフォルダを混ぜない**（前回の実行結果が紛れ込む）。

**結果が保存されずに画面に直接返ってきた場合**（件数が少ないページで起きる）：
そのページのJSONをそのまま作業フォルダに `page_NN.json` として書き出し、
STEP 3で `--glob` を追加して一緒に読ませる。

## STEP 3｜社外ドメインに畳む

```bash
<python> ~/.claude/skills/aio-target-lister/scripts/extract_domains.py \
  --glob "<tool-resultsのフォルダ>/*search_threads*.txt" \
  --out "<作業フォルダ>/companies_raw.json" --csv "<作業フォルダ>/companies_raw.csv"
```

（STEP 2で `page_NN.json` を書き出した場合は `--glob "<作業フォルダ>/page_*.json"` を足す）

やっていること：

- 送信者の最多アドレスを**自分のアドレスとして自動判定**し、そのドメインを自社として除外
  （出力の「自分のアドレス(自動判定)」を必ず確認する。共有メールボックスなどで外れたら `--me` で指定し直す）
- 提供元（ライトアップ `writeup.co.jp`）を除外。パートナーが使うと提供元とのやりとりが大量に出るため。
  ライトアップ社員が使う場合は自社として除外される
- フリーメール・ツール自動通知・`no-reply` 系を除外
- `mail.example.co.jp` と `example.co.jp` を同じ会社に畳む
- 接触回数・初回/最終接触日・件名を会社ごとに集約
- スニペットから**社名**（相手の返信や宛名の「株式会社〇〇」）と**担当者名**（送信メール冒頭の「〇〇さま」）を拾い、
  `company_name` と `contacts[{address, name}]` に入れる。3社以上に出てくる社名は自社名として捨てる。
  利用者の社名が拾われてしまう場合は `--own-name 社名` で除外語を足す
- `MAILER-DAEMON` / `postmaster` からの通知に出てくるドメインをバウンスとして記録

出力を見るときは**最終接触の新しい順**に並んでいる。関係が生きているうちに
出すのがいちばん通るので、この順序は崩さない。

除外の内訳（`excluded_counts` と `excluded_samples`）は台帳の「除外したもの」欄に
そのまま載せる。判断が違えば戻せる状態にしておくのが、リストを信用してもらう条件。

社外ドメインが0〜5件しか出なかったら、判定の前に止めて原因を確かめる
（期間が短すぎる、別アカウントのGmailにつながっている、など）。

## STEP 4｜相性を判定する

まず `references/aio_product.md`（商材仕様）と `references/rubric.md`（判定軸・Tier・カテゴリ）を
読む。判定に入る前に必ず読む。

判定の材料は**件名とドメイン名しかない**。だからこそ、どこまでが事実で
どこからが推定かを行ごとに持たせる：

- `tag: "aio"` … 件名に「AIOの件」等があり、商談がすでに動いている
- `tag: "fact"` … 件名から業務内容が確認できた
- `tag: "ask"` … ドメイン名からの推定。業種は `要確認` にする

ドメイン名だけで業種を決めた会社に `fact` を付けない。台帳の価値は網羅性ではなく、
**推定を推定と分かる形で出していること**にある。ここを曖昧にすると、営業が推定を
事実として商談で喋り、一度で関係が壊れる。

`note` には根拠を短く書く。件名の引用と日付を入れると、営業がそのまま
「先日の◯◯の件ですが」と切り出せる。Tier S には最終接触からの日数も書く。

判定結果を `<作業フォルダ>/ledger.json` にまとめる。スキーマは `references/ledger_schema.md`。
社数が多い（150社超）ときは、Tierごとに分けて書き足していくと取りこぼしにくい。

## STEP 5｜台帳を組む

```bash
<python> ~/.claude/skills/aio-target-lister/scripts/build_ledger.py \
  "<作業フォルダ>/ledger.json" -o "<作業フォルダ>/AIO提案先台帳.html"
```

同時に、同じ中身の一覧表 `AIO提案先台帳.csv` が台帳の隣に書き出され、台帳の上部に
**「CSVをダウンロード（Excel可）」ボタン**が付く（BOM付きUTF-8なのでExcelでも文字化けしない）。
CSVは台帳と同じ並び・同じ判定から作るので、手で別に作らない。

### 5-2. Googleスプレッドシートにする（Google Driveがつながっている場合だけ）

ToolSearch で `google drive create_file` を探し、Google Driveの `create_file` が使えるときだけ行う。
使えなければ飛ばし、報告で「Google Driveをつなげばスプレッドシートにもできます」と1行添える。

1. `AIO提案先台帳.csv` を読み、**先頭のBOMを除いた全文**を `textContent` に、`contentMimeType: "text/csv"`、
   `title: "AIO提案先台帳_<YYYY-MM-DD>"` で `create_file` する（自動でスプレッドシートに変換される）
2. 返ってきたファイルIDから `https://docs.google.com/spreadsheets/d/<ID>/edit` を作り、
   `ledger.json` の `sheet_url` に入れて STEP 5 のビルドをやり直す。台帳の上部に「スプレッドシートで開く」が出る
3. `get_file_metadata` で先頭行が見出し（ランク,ランク名,会社名…）になっていることを確かめる

作られたスプレッドシートは利用者本人のマイドライブにあり、本人しか見られない。**共有設定は変えない**
（取引先の一覧なので、共有するかは利用者が決める）。

集計値と各Tierの社数は**データから数えられる**ので、書かない。手で書くと
必ずズレて、「161社」と言いながら内訳が132社という台帳ができる。数字が合わない
台帳は営業現場で一度で信用を失う。

`cat` の未定義値・`domain` の重複・空のTierはビルド時に落ちる。落ちたら直す。

デザイン（藍と山吹、Zen Old Mincho × Noto Sans JP、営業台帳としての高密度レイアウト）は
`assets/ledger_template.html` に固定してある。**毎回組み直さない。**
ライト/ダーク両対応とスマホ幅は検証済みなので、CSSに手を入れると壊れる。

## STEP 6｜検証して納品する

ブラウザペインで開いて、次の4点だけ確認する。過去に実際に壊れた箇所：

1. フィルタのチップを押して行が絞られ、件数表示が追随するか
2. 検索で該当0件のとき、空状態のメッセージが出るか
3. ダークモードで文字が読めるか（チップの文字色が落ちやすい）
4. スマホ幅で横スクロールが出ないか

納品は**HTMLファイルで渡す**。台帳は取引先の一覧そのものなので、
Artifactなどでの公開は**利用者が明示的に頼んだときだけ**にする。頼まれた場合も
「取引先の社名とメールの件名が載っています。社外に見える場所に置かないでください」と
一言添える。

中間ファイル（`companies_raw.*` / `ledger.json`）は作業フォルダに残す。
次回の差分確認や、判定の手直しに使える。

### 報告の型

台帳を渡すだけだと読まれない。次の順で、数字を頭に置いて報告する。

1. **母数** — 何スレッド走査して、何社取れたか。自動判定した自分のアドレス
2. **いま動いているもの** — AIO商談が稼働中の会社と、最終接触からの日数。ここの追いかけが最短
3. **再販・紹介が組める先** — 顧客基盤を持つ会社を名指しで3社程度。紹介条件はライトアップ担当に相談のうえ、と添える
4. **確からしさの申し添え** — 社名・日付・件名は事実、業種と相性ランクは推定を含むこと。`推` を付けた会社数
5. **届かなかった宛先** — バウンスしている会社。アドレスの棚卸しが要る
6. **未了** — 走査を打ち切った範囲、取りこぼしの可能性
7. **台帳の場所と開き方** — 作業フォルダのフルパス。「ダブルクリックでブラウザが開きます」。
   一覧表は台帳上部のボタンからCSVで落とせること、スプレッドシートを作った場合はそのリンク

Tier Cを「AIOに向かない」と要約しない。ほとんどは**件名からAIO文脈が読み取れなかった**
だけで、断定すると営業が有望な先を自分で消してしまう。

### 宿題の形に落とす

台帳を渡して終わりにせず、最後に次の3行で締める。
リストは作った瞬間が最も熱く、翌日には開かれなくなる。

> ①リストを作る（済） ②S〜Bから20社選ぶ ③上から3件、明日連絡する

1日3件で月60件の接触になる。提案数が足りない問題は、これで構造的に解決する。
続けて「1社目への連絡文の下書きも作りましょうか？」と1行だけ提案してよい
（作る場合も送信はせず、下書きまで）。

## 困ったとき

| 症状 | 原因 | 対処 |
|---|---|---|
| `python` でStoreが開く／見つからない | Python未導入、またはPATH未設定 | STEP 0-1 の案内を出す |
| Gmailのツールが見つからない | コネクタ未接続 | STEP 0-2 の案内を出す |
| 別人のメールが出てくる | 別のGoogleアカウントでGmailをつないでいる | 利用者に確認し、コネクタをつなぎ直してもらう |
| 自分のアドレス(自動判定)が違う | 共有メールボックス・代理送信が多い | `--me <正しいアドレス>` で再実行 |
| `送信メッセージ 0件` | 宛先や送信者が入らないviewで取得した | view を変えて STEP 2 からやり直す |
| 直近1年が既存パートナーや社内ばかり | 異動・育休などで接点が古い期間にある | 期間を `newer_than:4y` に広げる。アドレスが途中で変わっていれば `from:旧アドレス` でも走査し、`--me 新,旧` とカンマ区切りで渡す |
| 送信済みが自動返信・メルマガだらけ | 長期不在の自動返信、グループアドレス宛の配信が「送信済み」に入る | 自動返信の件名はスクリプトが除外する。走査量を減らすなら `from:自分のアドレス -subject:不在` で検索する |
| `スレッドのファイルが見つからない` | tool-results のフォルダ違い、または結果が保存されなかった | `ls -dt` で探し直す／`page_NN.json` を書き出す |
| 社外ドメインが極端に少ない | 期間が短い、送信の多くが社内宛て | 期間を `newer_than:2y` に広げるか相談 |
| `[build_ledger] 入力エラー` | ledger.json の cat/tag/domain の誤り | エラー文のとおり直して再ビルド |
| 日本語が文字化けする | コンソールの文字コード | スクリプト側でUTF-8に寄せてある。ファイル自体は正常なので台帳を開いて確認 |

## 情報の扱い

- 読むのは送信済みメールの**宛先・件名・日付**まで。本文は台帳に載せない
- 台帳と中間ファイルは利用者のPCの作業フォルダにだけ置く。外部に送らない
- 台帳は取引先の一覧なので、社外共有・公開は利用者の判断に任せ、こちらからは勧めない

## 他商材に流用するとき

判定軸（`references/rubric.md`）と `criteria` の文面を差し替え、`references/aio_product.md` に
相当する商材仕様を用意すれば、そのまま別商材の提案先台帳になる。
STEP 0・2・3・5・6は商材に依存しない。

商材が変わると相性の良い業種も変わるので、**「掲載される余地があるか」に相当する問い**を
商材ごとに立て直すこと。そこを流用すると、それらしいが根拠のない台帳ができる。
